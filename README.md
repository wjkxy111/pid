# PID Lab 上位机

用于通过串口采集被控对象输入/输出数据。默认使用本地 NumPy 完成 FOPDT 模型辨识、
PI/PID/PIDF 候选搜索和闭环安全门限验收，不需要 Codex、网络或 MATLAB；安装了合法
MATLAB 环境时，也可以选择 System Identification Toolbox 与 `pidtune` 后端。辨识模型
还能用于 PSO 分层优化 K230 风格的串级、增益调度、前馈和输出约束参数。

## 当前功能

- USB 转串口、蓝牙 SPP 虚拟串口扫描与连接
- 连接后自动握手：识别设备 ID、固件版本、支持命令、单位和安全范围
- 按设备持久化档案，可编辑波特率、单位和 PID/激励/执行器范围
- `request_id` 事务匹配，过期或串包 ACK 不会被当成新一次 PID 写入确认
- JSON Lines 串口协议及实时波形
- 阶跃、PRBS、chirp 实验指令
- 数据保存/载入 CSV
- 完整 `.pidlab` 实验会话：归档设备、实验设置、原始数据、辨识、PID、效果评分和复杂控制结果
- 会话载入与两次实验指标对比，支持把基准输出曲线叠加到当前波形
- 会话采样数据 SHA-256 完整性校验；会话设备与当前设备不一致时禁止参数写入
- 一键“阶跃采集 → 本地辨识 → PID 搜索 → 闭环预验收”
- 纯 NumPy 的一阶惯性加延迟（FOPDT）辨识与 IMC 候选搜索
- 保守、均衡、快速三种自动调参策略，以及最低拟合度写入门限
- 基于 python-control 的 Bode、闭环极点、增益/相位裕度与灵敏度峰值分析
- 频域鲁棒性门禁：分析失败或任一门限不合格时自动禁止 PID 写入
- 设备当前 PID 读取、已生效参数持久化、历史版本选择和原子回退
- 基于真实闭环阶跃的效果评分与优化算法建议
- MATLAB Engine 调用 `tfest`、`compare` 和 `pidtune`
- 独立 MATLAB `.m` 算法文件，便于在 MATLAB 中单独调试
- 未激活期间的“接口模拟”模式（结果不可写入真实设备）
- PID 参数预览与串口回写
- 数据驱动的控制器参数注册表：新增算法或参数不需要重写串口传输层
- K230 串级球控模板：位置外环、速度内环、前馈/阻尼和执行器约束
- NumPy 实现的 PSO 模型优化器，可勾选参数并设置初值、上下限
- 通用 `set_controller` 消息，可只更新当前优化层的参数
- 无硬件模拟设备，便于验证完整流程
- 多场景模拟演示（标准/快/慢/强噪声/限幅死区）与本地 NumPy / MATLAB 同数据对比
- 串口读取、MATLAB 计算和 PSO 优化均在后台线程执行

Codex 只用于协助开发本工程，不是软件运行时的一部分。关闭 Codex 后直接执行
`python main.py`，本地自动调参仍可完整运行。

## 推荐的首次使用方式

- 第一次打开可点击顶部“模拟演示”，软件会连接内置对象并自动跑完采集、辨识和整定。
- 接真实设备前点击“恢复推荐设置”；该按钮恢复本地均衡 PIDF、8 秒阶跃和 20 ms 采样，
  但不会修改激励幅值，因为 PWM、电流、角度等设备单位不同。
- 顶部蓝色提示条始终显示当前应完成的步骤，进度条统一显示采集、本地整定和 PSO 进度。
- 未连接、数据不足或后台正在计算时，不可执行的按钮会自动禁用；“停止 / 取消”和真实设备
  的硬件急停应始终保持可用。
- PID 结果可以直接复制为 `set_pid` JSON，效果分析报告也可一键复制。
- 采样周期抖动低于 5% 显示绿色，5%~20% 显示橙色，超过 20% 显示红色并应重新采样。

## 安装与启动

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

Windows 用户也可以直接双击项目根目录的 `启动_PIDLab.bat`。脚本会优先使用已有的
`.venv`，否则使用系统 Python；检测到 PySide6、pyqtgraph、pyserial、NumPy 或
python-control 缺失时，会自动执行 `pip install -r requirements.txt`，然后启动上位机。
MATLAB Engine 是否可用仍由“MATLAB Engine（真实计算）”后端和“检查 MATLAB/许可证”按钮
单独判断。

只使用本地自动调参时，到这里即可，不需要安装 MATLAB Engine。

如需 MATLAB 辨识，在 MATLAB 安装目录的 Engine API 目录执行：

```powershell
cd "<MATLABROOT>\extern\engines\python"
python -m pip install .
```

MATLAB 需要 System Identification Toolbox 和 Control System Toolbox。
当前计算入口位于 `matlab/pidlab_identify_and_tune.m`。

## 串口协议

编码为 UTF-8，每条消息以换行结尾。

下位机上报：

```json
{"type":"sample","t":0.125,"u":35.0,"y":12.4,"setpoint":20.0}
{"type":"ack","command":"set_pid","ok":true,"request_id":"91f65a42db2f40ab"}
{"type":"status","message":"experiment started"}
```

上位机下发：

```json
{"type":"start","signal":"step","amplitude":40.0,"duration":8.0,"sample_time":0.02,"request_id":"e118951f455748a0"}
{"type":"stop","request_id":"f07088bb51b2440b"}
{"type":"set_pid","kp":1.2,"ki":0.4,"kd":0.03,"n":100.0,"request_id":"91f65a42db2f40ab"}
{"type":"set_controller","algorithm":"cascade_ball_balance","layer":"inner_velocity","params":{"VELOCITY_KP_NORMAL":0.04,"VELOCITY_KI_NORMAL":0.0012},"request_id":"2a70bb8670944de8"}
```

`t` 单位为秒，输入 `u`、输出 `y` 和设定值的物理单位由设备自行约定。采样周期必须稳定。

## 设备握手、档案与兼容模式

真实串口连接成功后，上位机先发送带 `request_id` 的 `hello`。新固件应回复
`capabilities`，包含稳定的 `device_id`、固件/协议版本、`supported_commands`、`units`
和 `limits`。上位机会选中该设备的持久化档案，并在实验、PID 写入和低幅闭环
验证前先做一次范围校验。

档案默认保存在 `%LOCALAPPDATA%\PIDLab\device_profiles.json`。固件未在 1.5 秒内回复
`capabilities` 时，软件进入旧固件兼容模式：基础采集、`get_pid` 和 `set_pid` 仍可用，
但不允许自动闭环验证或 `set_controller`，因为无法证明旧固件具备相应保护。

每条命令的直接响应必须原样回传 `request_id`。辨识实验和闭环验证的完成/中止消息
继续使用该次会话的 `request_id`。详细 JSON 示例见 `docs/device_protocol.md`。

## 一键本地自动调参（无需 Codex/MATLAB）

1. 连接设备或勾选“模拟设备”，选择 PI、PID 或 PIDF。
2. 设置一个低风险的阶跃幅值、实验时长和采样周期；真实设备先空载并限制 PWM/电流。
3. 点击“一键采集 + 本地自动调参”。上位机会强制使用带基线段的阶跃实验。
4. 采集结束后，上位机自动搜索输入延迟，拟合 `K/(T s + 1)`，再搜索满足所选安全策略的 PID。
5. 整定结束后自动打开频域安全分析；只有模型拟合度、时域预验收、闭环稳定性、增益/相位
   裕度和灵敏度峰值全部过门限时，“写入 PID 到设备”才会启用。
6. 检查模型曲线、频域曲线和参数后人工确认写入；第一次上车仍应低幅、空载、可硬件急停。

本地整定代码位于 `pidlab/local_autotune.py`。它不会把数据发往网络，也不调用大模型。
FOPDT 适合多数电机速度环的初始整定；强非线性、明显摩擦死区、时变对象或不稳定对象
应改用更合适的模型，并保持模型质量门限。

## 频域与稳定性安全检查

“频域 / 稳定性”页使用辨识得到的连续对象 `G(s)` 和当前并联 PID/PIDF 构造单位负反馈
开环 `L(s)=C(s)G(s)`。每次整定或载入完整会话后会自动重新分析，也可以修改门限后手动
分析。界面绘制开环、灵敏度 `S=1/(1+L)`、互补灵敏度 `T=L/(1+L)` 和开环相位，并显示：

- 闭环极点以及是否严格位于左半平面；
- 相位裕度 PM，默认至少 30°；
- 增益裕度 GM，默认至少 6 dB；
- 灵敏度峰值 Ms，默认不超过 2.0。

以上任一指标无法确定或未通过时，软件保留结果供诊断，但锁定“写入 PID 到设备”。门限
可以按机构风险收紧；不应为了解锁写入而随意放宽。该分析只对辨识模型负责，未建模的纯
延迟、摩擦、饱和、采样/计算延迟和工况变化仍需依靠固件硬限制及低幅闭环验证控制风险。

## 模拟演示与 MATLAB 对比

顶部“模拟演示”用于快速跑通单一工况；辨识实验中的“模拟场景”下拉框可选择标准二阶、
快速对象、慢响应、强测量噪声和输入限幅+死区。顶部“对比演示”会用同一组模拟采样分别
调用本地 NumPy 和 MATLAB Engine，并在“频域 / 稳定性”页显示单位阶跃目标、两套闭环
响应、超调、调节时间、稳态误差和发散状态。

两套结果不同并不自动说明某一套更好：MATLAB 的 `tfest` 依赖模型阶次和激励频段。工程
入口会检查模型 DC 增益方向；单一阶跃下若高阶模型出现稳态方向错误且较低阶拟合更好，
会自动采用较低阶模型并在结果中说明。正式调参仍建议用 PRBS/chirp 复核，并以真实闭环
低幅验证结果为准。

## 参数版本和回退

1. 固件实现 `get_pid`/`pid_state`，并保证 `set_pid` 先完整校验、后原子生效。
2. 在“效果分析 / 回退”页点击“读取设备当前 PID”，先把上电时已有参数纳入历史。
3. 每次 `set_pid` 得到设备成功确认后，上位机自动保存一个“已生效版本”；仅计算但未写入的
   候选参数不会混入回退历史。
4. 选择任意历史版本并点击“回退到所选版本”。设备确认后，该回退动作会保存成一个新版本，
   因此整个过程可审计，旧记录不会被覆盖。

历史默认保存在 `%LOCALAPPDATA%\PIDLab\pid_history.json`，关闭 Codex 或重启上位机后仍保留。

## 根据真实效果给出算法建议

采集或载入闭环阶跃 CSV，然后在“效果分析 / 回退”页填写执行器绝对限幅并点击分析。固件
必须上报真实 `setpoint`、`y` 和限幅后的实际 `u`。工具会计算综合评分、超调、10%~90%
上升时间、5% 调节时间、稳态误差、尾部振荡、控制量变化和饱和率，并按现象建议：

- 静差大但未饱和：PI/PIDF、小步增加 Ki、保留抗积分饱和；
- 超调或振荡：保守 IMC、降低 Kp/Ki、PIDF/低通，或用带超调惩罚的 PSO；
- 输出饱和：目标斜坡、抗饱和、前馈和带输出约束的 PSO，避免盲目增加积分；
- 多工况差异明显：增益调度；外环目标和内环动态耦合明显：串级控制；
- 噪声主导：优先 PI、导数滤波或状态估计，不使用裸 D。

若当前已生效版本的实测评分比上一已评分版本低 8 分以上，界面会明确给出回退建议。

## 自动闭环验收与失败回退

写入新 PID 后，可以把调参、效果分析和版本回退串成完整闭环：

1. 在“效果分析 / 回退”页先读取设备当前 PID，确保上位机历史与设备实际参数一致。
2. 历史中必须同时存在当前版本和至少一个不同的回退版本；填写真实执行器绝对限幅。
3. 设置一个低风险验证目标、持续时间、采样周期以及最低评分、最大超调、最大稳态误差和
   最大饱和率。
4. 点击“低幅闭环验证（不合格自动回退）”并进行一次安全确认。
5. 验证期间若输出触发紧急超调或执行器连续饱和 1 秒，上位机立即中止；参考固件也会在本地
   独立检查紧急超调和传感器异常。
6. 正常结束后自动分析。全部门限通过则发送 `accept_pid`；任一指标失败、人工停止或确认超时
   都会自动发送上一版本，并把回退保存成新的历史记录。

参考固件采用两阶段验收：验证结束后等待 `accept_pid`，3 秒内未收到最终确认就自行恢复回退
参数。因此即使上位机在验证末尾崩溃或通信中断，候选 PID 也不会被静默保留。真实产品仍需
根据电机和机械结构缩小固件中的目标、PID、PWM/电流及超调硬限制。

## 使用现有数据整定

1. 连接设备或勾选“模拟设备”。
2. 选择阶跃/PRBS/chirp，设置幅值、时长和采样周期并开始采集。
3. 停止实验，保存原始 CSV。
4. 选择“本地 NumPy 自动调参”，设置策略和最低拟合度，然后点击“用当前数据辨识并整定”。
5. 如已安装合法 MATLAB，也可切换 MATLAB Engine 后端并设置极点数、零点数。
6. 在“频域 / 稳定性”页确认闭环极点、PM、GM 和 Ms 通过门限，再将参数写入设备。

## 实验会话、恢复与对比

正式调参建议优先点击“保存会话”，生成 `.pidlab` 文件。它是一个可移植压缩包，内部保存
带 SHA-256 校验的原始 `samples.csv`，以及设备 ID/固件版本、激励设置、辨识模型、标准 PID、
效果评分、算法建议和复杂控制器优化结果。文件损坏或采样数据被修改时，软件会拒绝载入。

- “载入会话”恢复完整实验环境和结果；“导入 CSV”只恢复 `t/u/y/setpoint` 原始数据。
- “与会话对比”把当前实验与所选基准会话比较，并用紫色虚线叠加基准输出。
- 对比表包含拟合度、闭环评分、超调、上升/调节时间、稳态误差、尾部波动、饱和率及 PID 参数。
- 会话记录稳定的 `device_id`。载入其他设备的会话仍可离线分析，但在设备 ID 匹配前禁止写入
  PID 或复杂控制器，避免把一辆车或一块板的参数误写到另一台设备。
- CSV 仍适合 MATLAB、Python、Excel 或 PlotJuggler 等外部工具；`.pidlab` 用于完整复现实验。

## 复杂控制器 / PSO 流程

1. 先采集真实输入/输出并完成本地或 MATLAB 传递函数辨识；接口模拟只用于联调界面。
2. 打开“复杂控制器 / PSO”，选择 K230 串级球控模板和优化层级。
3. 指明辨识模型的输出是速度还是位置，设置仿真目标、时长、粒子数和迭代次数。
4. 在参数表中设置初值、上下限，只勾选本轮需要优化的少量参数。
5. 建议依次优化速度内环、位置外环、补偿与约束，最后才做少量核心参数的联合优化。
6. 检查目标函数、超调、调节时间、饱和比例及响应曲线，再复制 JSON 或写入设备。

复杂优化器复现的是控制核心，不会假装完整复现 K230 程序中的任务状态机、终点锁存、
静差恢复、视觉异常处理及机械非线性。得到的参数仍须在限幅、急停和低幅条件下逐层验证。

## 如何增加新算法或新参数

在 `pidlab/controllers.py` 中增加 `ControllerSchema` 和 `ParameterSpec`；界面会根据注册表自动
生成参数行，协议会将勾选的结果放进 `params` 对象。随后在 `pidlab/optimizer.py` 中增加对应
控制律/仿真分支，并在固件中按 `algorithm` 和 `layer` 原子校验、应用参数即可。传输层不需要
为每个算法增加一套新帧格式。

没有 MATLAB 或许可证时，直接使用默认的“本地 NumPy 自动调参”；这是根据真实采样数据
计算的独立后端。只有“接口模拟”模式是假数据联调，因此该模式结果禁止写入真实设备。

下位机协议详见 `docs/device_protocol.md`，Arduino 风格参考固件位于
`examples/arduino_reference/arduino_reference.ino`。该示例演示能力握手、基础采集、
`get_pid`/`set_pid` 和两阶段闭环验证；复杂控制器固件仍须按协议文档自行实现
`set_controller` 的参数白名单、范围校验和原子更新。

## GitHub 架构参考

- [System_Identification](https://github.com/Skylark0924/System_Identification)：MATLAB 系统辨识，以及速度环优先、位置环随后整定的串级思路。
- [pyPIDTune](https://github.com/PIDTuningIreland/pyPIDTune)：采集过程反应曲线、整定、仿真与设备模拟的完整工作流。
- [Ball-Balancing-PID-System](https://github.com/giusenso/Ball-Balancing-PID-System)：双 PID、串口通信和模块化执行器架构。
- [aerial_balance_bench](https://github.com/Wenminggong/aerial_balance_bench)：串级 PID、状态预测和模型控制的仿真到实机验证结构。
- [pyswarm](https://github.com/eggzec/pyswarm)：带约束 PSO 接口设计参考；本项目使用自己的轻量 NumPy 实现，不引入该运行时依赖。
- [python-control](https://github.com/python-control/python-control)：本项目实际使用的开源控制系统分析库，用于传递函数、反馈、稳定裕度和频率响应计算。

首次接真实设备时应限制输出幅值并准备急停。自动辨识得到的是初值，不应在无人监护下直接应用到高功率设备。
